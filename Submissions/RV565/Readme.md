## Description

RV565 is a video container for microcontrollers driving small displays.
Frames are stored in the display's own pixel format, so a player only
decompresses and transfers them. A little-endian header (magic `RV5`,
version, width, height, frames per second, flags, frame count) is followed by
one record per frame: a 32-bit length and the frame data. There is no audio
track. Files are typically created on a computer (Python tool, in-browser
converter, FFmpeg patch) and played on ESP32 or RP2350 boards.

**Version 6**: a 12-byte header; every frame is an independent zlib stream
that inflates to exactly width × height × 2 bytes of big-endian RGB565
pixels, so any frame can be decoded on its own.

**Version 7**: the header grows to at least 16 bytes with a header size, a
pixel format (RGB565 big- or little-endian, packed RGB444, RGB666, RGB888, 8-
or 4-bit grayscale, 1-bit monochrome in rows or in 8-row pages), a codec
(stored or zlib) and a keyframe interval. Each record starts with a frame
type: a keyframe, a delta (XOR with the previous frame), a repeat, or a
partial delta (only the bands of lines that changed). Every frame at a
multiple of the keyframe interval is a keyframe, so seeking needs no scan.
Version 6 files remain valid, and version 7 readers read them.

## New Signature

RV565 Video, version 6 \
BOF ```52563506{4}[01:1E]{7}78```

| Bytes | Meaning |
| --- | --- |
| `52 56 35` | ASCII `RV5` |
| `06` | container version 6 |
| `{4}` | width and height (u16 each) |
| `[01:1E]` | frames per second, 1–30 |
| `{7}` | flags (1 byte), frame count (2), first frame length (4) |
| `78` | zlib header of the first frame (CMF byte: deflate, 32 KiB window) |

Flags are left out of the signature because readers must ignore unknown bits.

RV565 Video, version 7 \
BOF ```52563507{4}[01:3C]{3}10[00:08][00:01][01:FF]{4}00```

| Bytes | Meaning |
| --- | --- |
| `52 56 35` | ASCII `RV5` |
| `07` | container version 7 |
| `{4}` | width and height (u16 each) |
| `[01:3C]` | frames per second, 1–60 |
| `{3}` | flags (1 byte), frame count (2) |
| `10` | header size 16, as every version 7 writer writes it |
| `[00:08]` | pixel format |
| `[00:01]` | codec: stored or zlib |
| `[01:FF]` | keyframe interval |
| `{4}` | first record length |
| `00` | first frame type: keyframe (frame 0 is always a keyframe) |

## Sample

`rv565-v6-sample-testpattern.rv565`: 24 frames of scrolling colour bars,
180 × 135, 24 fps, 6,322 bytes, SHA-256
`5908de84764962132f31543df0ca2276d10d7744fa2c292caf5fde3f66faa8a7`.
Generated by the reference tool (`rv565 testpattern`); free to redistribute.

`rv565-v7-sample-rgb565be-zlib.rv565`: version 7, 21 × 13, 12 fps, 10 frames
(keyframes, deltas and a repeat), RGB565 big-endian, zlib, keyframe interval
4, 1,800 bytes, SHA-256
`6f167ced969161ca77d5bbb94b8273cace4ff038225793a1d0cf492658368861`. One of the RV565
conformance files (`tests/data/v7/rgb565be_zlib_k4.rv565`, listed with each
decoded frame's hash in `tests/data/v7/manifest.json`); free to redistribute.
